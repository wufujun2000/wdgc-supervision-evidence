## 一、这份素材的使用方式

本文提供已经拍板的身份权限规则，以及可供第三方评审组织产品 PRD 与原型工作的素材。技术团队不以此文直接指导产品团队。

当前先由技术团队完成底层和核心租户业务逻辑。课题组原始材料中的冲突按第三方评审既有结论登记，其提供的节点等内容仅作为后续可由平台功能填充的基线数据，**不等待课题组回复，不阻塞技术底座与核心租户逻辑**。

技术实现与验收完成后，还需补充真实实现范围、流程状态、接口与页面能力、验收证据和限制，并连同本素材提交第三方评审。第三方评审结合其既有推进路线，形成正式的专业推进文档、统一开发口径和产品交接文件，再由项目负责人分发。以下产品向内容均为评审可采用的草案，不是技术团队直接发布的任务要求。

## 二、先统一三个概念

### 1. 登录账号

表示“这个人能登录系统”。账号本身不等于任何企业或项目权限。

### 2. 租户成员

表示“这个人属于哪家企业，以及能在企业里做什么管理工作”。

产品界面建议使用“企业成员”或“租户成员”，不使用“会员”。

### 3. 项目成员

表示“这个人在哪个项目担任总监、专监或监理员，以及负责哪些危大类别”。

**企业身份和项目身份是两回事。** 一个人是企业拥有者或企业管理员，不代表他天然是任何项目的总监、专监或监理员。

## 三、角色及正式名称

| 所属范围 | 系统标识 | PRD/界面统一名称 | 说明 |
| :--- | :--- | :--- | :--- |
| 平台 | `SUPERADMIN` | 平台超级管理员 | 平台最高管理人员，可按规定兜底处理企业拥有者移交 |
| 平台 | `SYSADMIN` | 平台系统管理员 | 负责租户开通、平台配置等日常工作 |
| 企业 | `TENANT_OWNER` | **企业拥有者** | 每家企业恰好一人，是企业内唯一超管 |
| 企业 | `TENANT_ADMIN` | **企业管理员** | 可有多人，由企业拥有者授权，权限可以不同 |
| 项目 | `SZ` | 总监 | 按项目任命，负责项目级审批、终审及法定签发 |
| 项目 | `SP` | 专业监理工程师（专监） | 按项目任命，并指定负责的危大类别 |
| 项目 | `SA` | 监理员 | 按项目任命，主要处理本人任务和现场采集 |

命名注意：

- “企业拥有者”是系统中的所有权身份，不表示现实中的股权或法定代表人身份；
- 租户侧统一称“企业管理员”，不要写成容易与平台系统管理员混淆的“系统管理员”；
- “租户超管”仅可用于解释企业拥有者，不作为另一个角色，也不作为 PRD 正式名称。

## 四、企业拥有者与企业管理员

### 4.1 企业拥有者

- 每家企业任意时刻只有一名；
- 平台开通企业时，首名企业成员自动成为初始企业拥有者；
- 默认拥有全部企业管理权限；
- 不能通过普通“分配角色”功能新增第二名企业拥有者；
- 只能通过专门的“移交企业拥有者”流程变更；
- 不因该身份自动获得项目签署权。

### 4.2 企业管理员

- 可以没有，也可以有多名；
- 权限由企业拥有者或具有相应管理权限的管理员分配；
- 可以获得全部**可委托管理权限**，因此日常功能可能看起来与企业拥有者几乎相同；
- 即使权限看起来相同，也仍然不是企业拥有者，不能执行所有权专属操作。

### 4.3 产品必须表达的差异

| 操作 | 企业拥有者 | 企业管理员 |
| :--- | :--- | :--- |
| 新增、停用企业成员 | 默认可以 | 获得相应权限后可以 |
| 设置企业管理员、分配管理权限 | 默认可以 | 获得相应权限后可以，且不能越权授权 |
| 创建项目 | 默认可以 | 获得项目管理权限后可以 |
| 任命项目总监、专监、监理员 | 默认可以 | 获得项目任命权限后可以 |
| 移交企业拥有者 | 可以 | **永远不可以** |
| 停用、删除或降权企业拥有者 | 不能通过普通成员管理操作 | **永远不可以** |
| 直接以企业身份进行项目法定签署 | 不可以，仍需项目任命 | 不可以，仍需项目任命 |

“拥有全部可委托权限”不等于“可以替代企业拥有者”。页面和权限说明中必须明确这一点。

## 五、项目角色必须按项目任命

总监、专监、监理员不是企业级角色。

同一个人可以：

- 在项目 A 担任专监，负责基坑和起重两类危大工程；
- 在项目 B 担任总监；
- 在项目 C 不担任任何项目角色。

项目任命规则：

1. 只有具备项目任命权限的企业拥有者或企业管理员可以任命；
2. 任命对象必须是本企业的有效成员；
3. 专监必须指定其在该项目负责的危大类别；
4. 总监负责当前项目全部危大类别；
5. 监理员主要处理当前项目分派给本人的任务和本人采集记录；
6. 项目角色变更不能改写历史采集、审核、签署记录中的当时身份。

## 六、需要覆盖的核心业务流程

### 6.1 平台开通企业并产生首名企业拥有者

1. 平台填写企业基本信息；
2. 创建或绑定首名成员的登录账号；
3. 形成首名企业成员；
4. 系统将其设为企业拥有者；
5. 全流程成功才算开通成功，不能出现“企业已开通但没有拥有者”的可用状态。

产品需设计：开通表单、首名成员信息、结果确认、失败提示及开通记录。

### 6.2 企业新增成员并设置管理员

1. 有成员管理权限的人新增或绑定成员；
2. 有管理员管理权限的人将其设为企业管理员；
3. 在允许授权范围内勾选管理权限；
4. 普通成员没有被授予企业管理权限时，不显示相应管理入口。

产品需设计：成员列表、成员详情、新增/停用、管理员标识、权限配置、权限差异展示及不可越权提示。

### 6.3 创建项目并任命成员

1. 有项目管理权限的人创建项目；
2. 有项目任命权限的人从本企业有效成员中选择项目成员；
3. 分配总监、专监或监理员；
4. 为专监选择负责的危大类别；
5. 成员进入项目后只看到自己权限范围内的功能与数据。

产品需设计：项目创建、项目成员列表、角色任命、专监危大类别配置、角色变更及生效反馈。

### 6.4 移交企业拥有者

有两条路径：

- **企业内移交**：当前企业拥有者发起，选择本企业其他有效成员；
- **平台兜底移交**：具有专门权限的平台管理员发起，用于原拥有者离职、停用或失联等情况，必须填写原因。

移交确认页必须明确展示：

- 当前企业拥有者和接收人；
- 接收后立即成为新的企业拥有者；
- 原拥有者立即失去该身份和超管权限；
- 双方已有项目任命和历史记录不变；
- 原拥有者仍保留企业成员身份，如需要企业管理员权限，由新拥有者另行授予；
- 操作需要二次确认，双方可能需要重新登录。

一期采用确认后直接生效，不设计“等待接收人接受”的流程。

## 七、权限不足和异常场景

PRD 与原型至少覆盖：

1. 企业管理员未获得成员管理、项目管理或项目任命权限时的入口展示与拦截；
2. 企业管理员尝试移交企业拥有者、停用企业拥有者或越权授权时的拒绝提示；
3. 选择其他企业成员、已停用成员作为所有权接收人时的拦截；
4. 原拥有者移交后继续使用旧会话时的失效处理；
5. 企业被冻结、账号被停用、成员被停用后的登录和访问反馈；
6. 未被任命到项目的人访问项目功能时的反馈；
7. 专监访问未分配危大类别时的反馈；
8. 企业拥有者或管理员未被任命为总监时，尝试执行总监法定签署时的拒绝提示；
9. 平台无专门权限的管理员尝试兜底移交时的拒绝提示。

所有权限拦截都以服务端结果为准，前端隐藏按钮只用于改善体验。

## 八、平台代管与企业拥有者无关

平台超级管理员按规定发起受控代管时：

- 默认只读；
- 特定操作需要二次授权；
- 全程审计；
- 不得代签或修改、删除原始证据；
- 不因此成为企业拥有者；
- 不获得企业日常管理身份。

PRD 不应把“平台超级管理员”“平台代管身份”“企业拥有者”画成同一个角色。

## 九、PRD 和原型交付清单

请产品团队至少形成以下内容：

1. **角色与术语章节**：使用本文统一名称，区分平台、企业、项目三个范围；
2. **角色权限矩阵**：分别列出企业管理权限和项目业务权限，不把两类权限混在一张无范围区分的表里；
3. **平台端页面**：企业开通、首名拥有者、平台兜底移交及审计记录；
4. **租户端页面**：成员管理、管理员设置与权限分配、企业拥有者移交、项目管理、项目成员任命、专监危大类别配置；
5. **移动端规则**：当前项目、当前项目角色、专监危大类别和权限不足表现；
6. **流程与状态**：开通、成员新增/停用、权限授予/回收、项目任命/变更、所有权移交；
7. **异常与提示文案**：覆盖第七节场景；
8. **验收用例**：至少覆盖“唯一拥有者、管理员不能替代拥有者、项目角色跨项目独立、专监危大范围、移交后权限即时生效、历史归属不变”。

## 十、产品可以细化、但不能改变的内容

产品可以细化：

- 页面布局、操作入口、字段展示、表单校验和提示文案；
- 成员邀请或账号绑定的具体交互；
- 管理员权限的分组展示与选择方式；
- 项目任命和变更的具体操作流程；
- 审计记录的查询与展示方式。

不得自行改变：

- 每家企业只有一名企业拥有者；
- 企业拥有者与企业管理员的身份差异；
- 企业管理员不能通过授权获得所有权专属能力；
- 总监、专监、监理员按项目任命；
- 企业角色不自动产生项目法定签署权；
- 平台执行移交不等于平台成为企业拥有者。

如业务确需多名企业拥有者、租户级总监或管理员移交所有权等变化，必须作为重大架构变更重新提交技术评审，不能仅在 PRD 中直接改写。

---

**一句话交接口径：平台管角色规则和租户开通，企业拥有者管企业授权，企业管理员按授权协助管理，总监/专监/监理员按项目任命；企业拥有者唯一且只能移交，管理员权限再全也不是拥有者。**
