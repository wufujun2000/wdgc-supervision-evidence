# 产品 PRD 第一段 · Agent 起草指令模板（2026-11-25）

> **用法**：产品团队把 5 份材料＋本指令交给文档写作 Agent，产出"PRD 第一段**初稿**"；产品负责人人工定稿后提交第三方 E 复审。
> **为什么可行**：第一段的技术事实（角色/权限/项目/移交）已实现、已拍板、已 E 复审——材料里全是"确定的事实"，Agent 翻译事实，不是猜未来。
> **为什么仍需人**：材料明确"可细化"的部分（页面布局/文案/提示语气/邀请交互）是产品决策，Agent 只能拟稿，人拍板。

---

## 一、给 Agent 的指令（可直接粘贴）

【角色】你是产品 PRD 撰写助手，基于且仅基于我提供的 5 份材料起草 PRD 第一段初稿。

【输入材料】（唯一事实来源，禁止使用材料之外的"常识/记忆"补充规则）
1. 《PRD-v3-骨架与两段衔接说明》（章节骨架与写作规则）
2. 《专业推进文档与统一开发口径》（背景与 7 角色统一口径）
3. 《产品交接-租户身份与权限体系》（第一段详细依据）
4. 《notice-产品团队》（任务范围）
5. 《新契约结构决策单》（仅供了解第二段方向，**不据此写第二段**）

【任务】按材料 1 §二的骨架，撰写 PRD v3.0 的第一段初稿：
- 第 1/2/3/4 章：按材料 1/2/3 组织（文档说明/背景与一期边界/用户与角色/总体设计）；
- 第 5 章**只写 5.1~5.3**（平台开通与兜底移交/企业成员与管理员与拥有者移交/项目与任命含专监危大绑定），按材料 3 §五的四条核心流程与 §六的 9 条异常场景展开；
- 第 7 章通用非功能框架（性能/安全/隐私）；V/P 留存细节不写；
- 第 8 章：站点地图**覆盖全部页面**（第二段页面列名占位）；第一段页面（开通/成员管理/管理员与权限配置/拥有者移交/项目管理与任命）逐页说明功能、字段、操作与状态反馈；
- 第 9 章：验收用例按材料 3 §八的最低覆盖清单逐条成文（每条含前置条件/操作步骤/预期结果/严重级别）。

【硬约束】
1. **占位不得填充**：5.4~5.7 与第 6 章保持占位，统一写"【第二段：待 B6 生成物/契约交接】"，一个字都不补；
2. **不得改变清单**：材料 3 §七的 5 条红线逐条遵守；需要变更走技术评审，不得直接改写；
3. **不得发明**：材料没有的规则一律写"【待产品确认】"，禁止编造流程/权限/字段；
4. **术语锁死**：角色名、危大类别码、阶段码严格用材料 2 §2.1 与材料 3 §二的统一名称，不换词不增角；
5. **权限矩阵画成可扩展网格**：行＝7 角色，列＝业务域；企业域管理权限列填实，采集/审核/出证列留占位标【第二段】；
6. **规则溯源**：每条业务规则标注材料出处；文末附《规则溯源表》（PRD 条目号 → 材料 x §y）。

【产出物】
1. PRD v3.0 第一段初稿（完整目录骨架＋第二段占位）；
2. 规则溯源表；
3. 第一段页面清单与交互要点说明（供原型对照）。

【提交前自检】
- [ ] 5.4~5.7/第6章占位未被填充；
- [ ] 术语与材料完全一致（7 角色/类别码/阶段码）；
- [ ] 无材料之外的发明规则（"待确认"标注除外）；
- [ ] 9 条异常场景全部成文且与材料一致；
- [ ] 验收用例覆盖材料 3 §八全部要点；
- [ ] 溯源表完整可查。

## 二、人工环节（Agent 不能替代，产品负责人做）

1. **交互与文案拍板**：Agent 拟的页面说明/提示文案，负责人按材料 3 §七"可细化"范围审定修改；
2. **原型对照**：与在研原型核对，页面/流程不一致处以材料为准调整原型；
3. **定稿**：负责人签字后交第三方 E 复审（对 ADR-001＋B0 真实实现逐条复核）。
