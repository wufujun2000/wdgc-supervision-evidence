## 三、防断层：六条衔接规则＋一道复审关

### 3.1 技术层的"自然接缝"已经存在（PRD 照实写即可，无需发明）

- **项目任命 → 任务生成**：第一段实现的"专监绑定危大类别"（按项目）正是第二段"采集任务按 项目×危大×节点 装配"的输入接口——接缝在技术层已经焊好，PRD 两段各写各的半边，天然连通。
- **统一账号/成员 → 采集人/审核人**：第二段的"谁拍的、谁审的"身份全部来自第一段的成员体系，不存在第二套身份。
- **危大类别码 01~11**：两段共用同一套编码，第一段任命页已在使用。

### 3.2 六条写作规则（产品执行，防"两段连不上"）

1. **骨架不动**：目录按§二定死；第二段只在既有章节里填占位，**不得另起章节结构**。
2. **术语一次定死**：7 角色名、危大类别码、阶段码等全本通用术语在第一段定死，第二段**不换词**（统一以《专业推进文档》§2.1 与交接件§二为准）。
3. **信息架构一次画全**：站点地图覆盖全部页面（含第二段页面占位），避免第二段页面"塞不进"第一段画的导航。
4. **权限矩阵画成可扩展网格**：行＝7 角色，列＝业务域；企业域列第一段填实，采集/审核/出证列留占位标【第二段】——第二段填列不重排结构。
5. **占位统一格式**：所有第二段占位处一律写"【第二段：待 B6 生成物/契约交接】"，**禁止提前手写契约内容**（字段/命名/节点/采集规则）。
6. **逃生阀**：产品若认为业务上必须改已拍板内容（如角色规则），不得直接改写——按《产品交接》§七提交技术评审。
