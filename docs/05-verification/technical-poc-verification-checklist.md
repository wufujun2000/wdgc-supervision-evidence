# 危大工程监理履职证据链系统 —— 真机与云服务质量属性 PoC 验证清单（V1.0）

> **文档定位**：供研发、测试及第三方评审专家执行“限定范围原型与技术 PoC”使用，是将 `business_readiness` 从 `BLOCKED` 解除的必要技术证据。  
> **关联文档**：`docs/02-prd/PRD_v2.4_基线冻结版.md`、`docs/03-architecture/system-architecture-design.md`、`docs/04-baseline-data/validation_report.json`
> **验证原则**：真机实测、云服务实测、可复现步骤、保留原始证据（截图/日志/录屏/测试报告），不以文档承诺代替实测结果。

---

## 一、PoC 目标与完成标准

### 1.1 验证目标
在真实手机、真实微信小程序、真实阿里云 OSS/MinIO 与双租户数据环境下，验证危大工程现场采集、离线缓存、断点续传、哈希校验、权限隔离及法定履职闭环的可行性与边界。

### 1.2 完成标准（Definition of Done）
- [ ] 本清单 P0 项全部实测通过，并保留原始证据；
- [ ] 每项测试均记录测试机型、微信版本、网络条件、操作步骤、预期结果、实际结果与日志/截图；
- [ ] 形成《真机与云服务 PoC 验证报告》（含问题清单与整改建议）；
- [ ] 对未通过项明确限制条件与替代方案，不虚构“100% 支持”结论。

### 3.2 双哈希水印与元数据验证（TC-MOB-02）
- **步骤**：完成拍照后检查图片右下角水印、元数据 JSON 与服务端入库记录；
- **预期**：水印包含 `media_guid` 与 `raw_frame_sha256` 前 16 位；归档 `file_sha256` 由服务端独立计算并锁定，不与水印形成自引用；

### 3.3 离线沙箱 150MB 字节配额验证（TC-OFF-02/03）
- **步骤**：飞行模式下连续拍摄照片/视频，直至沙箱已用空间接近 150MB，再尝试继续采集；

### 3.4 网络恢复与 5MB 分片断点续传验证（TC-OFF-04/05）

## 四、P0 级哈希、存储与出证验证

### 4.1 全文件 SHA-256 防篡改变更验证（TC-SEC-01，非 WORM 测试桶/副本）

### 4.2 OSS WORM 合规保留验证（TC-SEC-02，真实 WORM 对象）
- **步骤**：对处于 WORM 保护期内的 ★强制影像调用 OSS `DeleteObject` / 覆盖 `PutObject`；

- **说明**：本用例验证“存储层拒绝篡改/删除”，不与哈希检测混为一个用例；
